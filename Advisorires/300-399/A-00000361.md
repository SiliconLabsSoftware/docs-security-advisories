### Source Product Impact Details

- EFx32 applications that print debug information through SWV or use ETM may be impacted.

## Description

- Some customers may assume that locking the debug interface will also disable SWO debug outputs and ETM, but it does not. To ensure sensitive information is not available through these functions, they must be removed or disabled prior to releasing the code to production.

- Serial Wire Viewer (SWV) is an ARM component that outputs processor state information from the Instruction Trace Macrocell (ITM) through the Serial Wire Output (SWO) pin.

- The SWO pin can also be configured as an IOStream for “printf” debugging. Since debug lock does not shut off SWO, applications that print out debug information through SWO may be leaking sensitive information past debug lock.

### Fix/Workaround

- Debugging print statements should be removed or disabled for all production code. To safely enable SWO printing for debugging, don’t enable SWO unless a debug session is open, and disable SWO if a debug session is not open: 

        if(DBG_Connected()){
            DBG_SWOEnable(1);
        } else {
            DBG_SWOEnable(0);
        }

- Existing solutions can be checked for this vulnerability by monitoring the SWO pin during operation of the locked device.
