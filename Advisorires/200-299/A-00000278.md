# Silicon Labs Security Advisory A-00000278 : Denial of Service on Zigbee end node caused by attacking its parent Coordinator or Router

Flags: Zigbee

CVSS Severity: Medium

CVSS Base Score: 6.5, Medium

CVSS Temporal Score: 5.9, Medium

CVSS String: CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H/E:P/RL:O/RC:C

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| EmberZNet | 6.10.1 and earlier | GSDK | 3.2.1 and earlier | - |

### Source Product Impact Details

- All Zigbee end devices connected to Coordinators or Routers running EmberZNet 6.10.1 or earlier, distributed in GSDK 3.2.1 or earlier

## Description

- This is an attack on a Coordinator or Router that causes a Denial of Service on its connected end device

- If an attacker can successfully disconnect an authorized end device from the network, they can use this vulnerability to send malicious packets to the parent Coordinator or Router to prevent the end node from successfully rejoining the network

- To keep the authorized end device from rejoining the network, this attack must be persistent. Once the malicious packets have stopped, the end device will be able to rejoin the network within a few minutes*
    - *Note that the recovery time on EmberZNet versions prior to 6.6.0 is around 4.2 hours

- This is related to Bug ID #719104

### Fix/Workaround

- This has been patched in EmberZNet 6.10.2 or later distributed in GSDK 3.2.2 or later

- An application-layer workaround for this issue is being investigated
