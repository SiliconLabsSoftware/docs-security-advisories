## Description

- This security advisory is intended to notify users that a security vulnerability was identified in a third-party product that is included in Silicon Labs products.
- BTM_ECDH_P256_CMAC_AES128_AES_CCM provisioning algorithm (Bluetooth Mesh version 1.0) is vulnerable to man-in-the-middle attacks if out-of-band authentication data is used.
- BTM_ECDH_P256_HMAC_SHA256_AES_CCM provisioning algorithm (Bluetooth Mesh version 1.1) is vulnerable to man-in-the-middle attacks if out-of-band authentication data with low entropy is used.
    - Low entropy output out-of-band actions like Blink, Beep, Vibrate as well as low entropy input out-of- band actions like Push and Twist are susceptible to brute force attacks.
    - Weak Authentication can lead to a Man-in-the-Middle attack.

### Fix/Workaround

- Use the recommended workaround, as this issue cannot be fixed in Silicon Labs’ current implementation.
- In Bluetooth Mesh version 1.0, if protection from active man-in-the-middle attack is desired, out-of-band- authentication should not be used.
    - Bluetooth Mesh version 1.0 should only be used when provisioning legacy devices that do not support Bluetooth Mesh version 1.1.

- For Bluetooth Mesh version 1.0 and 1.1 using an out-of-band public key for the device will block active MITM attacks.

- In Bluetooth Mesh version 1.1, if protection from active man-in-the-middle attack is desired, only the strongest entropy methods should be used.
    - If Output Alphanumeric or Input Alphanumeric authentication is used, a sufficient length of authentication data should be used to ensure adequate entropy.

- Using more than 128 bits of entropy for static authentication data blocks man-in-the-middle attack.

- Bluetooth Mesh Provisioning Security Best Practices can be found here: [https://docs.silabs.com/btmesh/latest/btmesh-provisioning-security-best-practices/](https://docs.silabs.com/btmesh/latest/btmesh-provisioning-security-best-practices/)
