Flags: Bluetooth Mesh

CVSS Severity: Medium

### Source Product Impact Details

- Impacts all Series 1 and Series 2 devices that support BT Mesh running GSDK 3.1.0 to Simplicity SDK 2024.06.0.
    - This includes xG12, xG13, xG21, xG22, xG24, xG27 devices. 
    
Please note: As of June 2024, the Gecko SDK was renamed to the Simplicity SDK, and the versioning scheme was changed from Gecko SDK vX.Y.Z to Simplicity SDK YYYY.MM.Patch#.

## CVE ID(s)

- [CVE-2024-4013](https://nvd.nist.gov/vuln/detail/CVE-2024-4013) [1] was reserved for this vulnerability.

## Description

- A bug exists in the API, mesh_node_power_off(), which fails to copy the contents of the Replay Protection List (RPL) from RAM to NVM before powering down, resulting in the ability to replay unsaved messages.

- At bootup, the RPL stored in NVM will be copied into RAM. As valid messages are received, the RPL in RAM will be updated. Before powering down, the RPL must be copied from RAM back into NVM to retain history of previously sent messages. If this does not occur, previously sent messages could be replayed.
    - This vulnerability is only present if RPL data is loaded from NVM to RAM on bootup. If no RPL data exists in NVM on bootup, it will not be copied into RAM, and in this case, this vulnerability will not be exploitable.

### Fix/Workaround

- An application layer workaround can be implemented if mesh_node_save_replay_protection_list(), is called before powering down, the RPL will be saved correctly into NVM, mitigating the replay vulnerability.
- An official fix to address this vulnerability is available in the latest release of the Simplicity SDK. As of June 2024, the Gecko SDK was renamed to the Simplicity SDK, and the versioning scheme was changed from Gecko SDK vX.Y.Z to Simplicity SDK YYYY.MM.Patch#.

- Customers are always recommended to upgrade to the latest SDK version to keep their firmware up to date with the latest vulnerability patches, bug fixes, and new features.
