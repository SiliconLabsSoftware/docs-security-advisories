## Description

- The report, found here [https://www.usenix.org/system/files/woot20-paper-wu-updated.pdf](https://www.usenix.org/system/files/woot20-paper-wu-updated.pdf), describes two weaknesses in the Bluetoooth specification.

- A well-designed application can defend against these vulnerabilities. The following are recommended:
    - Require encryption and authentication on all GATT characteristics
    - Require bonding for encryption
    - Terminate the connection if bonding fails
    - Actively enable encryption on all connections
    - Use LE privacy to limit MAC address cloning

### Fix/Workaround

- To protect against this attack, Bluetooth LE applications should use the following security features
    1. Enable authenticated read/write for any sensitive characteristics
    2. Enforce the option for encryption to require bonding
    3. Enable the option to require man in the middle (MITM) protection

- Optionally, design the client to request increased security upon forming any connection in addition to the suggestions above.

- Only allow bonded connections once a bond has been established.
