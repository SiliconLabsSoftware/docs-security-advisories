# Silicon Labs Security Advisory A-00000144 : Two Potential Denial-of-Service Vulnerabilities in Micrium OS Network HTTP

Flags: MCU

CVSS Severity: High

CVSS Base Score: 8.6, High

CVSS Temporal Score: 7.7, High

CVSS String: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:N/I:N/A:H/E:P/RL:O/RC:C

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| Micrium OS Network | 5.10.1 and earlier | - | - | [CVE-2020-13583](https://nvd.nist.gov/vuln/detail/CVE-2020-13583), [CVE-2020-13582](https://nvd.nist.gov/vuln/detail/CVE-2020-13582) |
| Mictrium uC/OS-II or uC/OS-III | 3.01 and earlier | - | - | [CVE-2020-13583](https://nvd.nist.gov/vuln/detail/CVE-2020-13583), [CVE-2020-13582](https://nvd.nist.gov/vuln/detail/CVE-2020-13582) |

### Source Product Impact Details

- Cisco Talos has reported two vulnerabilities, as described below, which will be disclosed on their [vulnerability reports page](https://talosintelligence.com/vulnerability_reports#disclosed) as TALOS-2020-1193 and TALOS-2020-1194.  

- Any EFR32/EFM32-based SoC/module running Micrium OS Network HTTP server version 5.10.1 or earlier

- Any device running Micrium uC/OS-II or uC/OS-III with uC/HTTP server version 3.01 and earlier

## Description

- A specially crafted URL can cause the HTTP server to crash, resulting in a denial of service. CVE-2020- 13582 has been reserved for this vulnerability

- A request for multipart content can lead to a crash if memory is not allocated for this content, resulting in a denial of service. The following CVE has been reserved for this vulnerability [CVE-2020-13583](https://nvd.nist.gov/vuln/detail/CVE-2020-13583)

### Fix/Workaround

- Workaround for [CVE-2020-13582](https://nvd.nist.gov/vuln/detail/CVE-2020-13582) is to add a test for a NULL pointer being returned if the ‘=’ boundary character is not found. The test should go immediately after the following line found in http_server_req.c
    p_val = Str_Char_N(p_val, len, ASCII_CHAR_EQUALS_SIGN); 
An appropriate error code should be set via p_err followed by a return from this function

- A workaround for [CVE-2020-13583](https://nvd.nist.gov/vuln/detail/CVE-2020-13583) is to ensure that memory is allocated for multipart content by setting the FormCfgPtr pointer in the HTTPs instance struct as described in the form section [here](https://doc.micrium.com/display/httpdoc/Parameters+Configuration)

- Micrium uC/OS-II and uC/OS-III are maintained by the open source community. Silicon Labs has reported these issues in uC/HTTP to the community via Github here and [here](https://github.com/SiliconLabs/uC-HTTP/issues/2) and has notified the custodians of uC/OS-II and uC/OS-III

- Fixes for these vulnerabilities in Micrium OS are planned for the first half of 2021. An update to this advisory will be issued as soon as the fixes are available. EFR32/EFM32 applications using Micrium OS Network HTTP server should upgrade once the fix becomes available using Simplicity Studio v5’s help -> Update Software -> Manage installed packages -> SDKs -> Micrium OS and click the Install button
