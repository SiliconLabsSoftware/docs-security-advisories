# Silicon Labs Security Advisory A-00000496 : Zigbee does not use hardware AES-CCM on parts without Secure Vault High (SVH)

Flags: Zigbee

CVSS Severity: Medium

CVSS Base Score: 6.2, Medium

CVSS Temporal Score: 5.4, Medium

CVSS String: CVSS:/3.1/AV:L/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N/E:U/RL:O/RC:C

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| EmberZNet  | 7.4.0 through 7.2.0 | GSDK | 4.4.0 through 4.2.0 | [CVE-2023-51392](https://nvd.nist.gov/vuln/detail/CVE-2023-51392) |

### Source Product Impact Details

- EFR32xG2x-based devices without Secure Vault High running EmberZnet SDK between 7.2.0 <= v < 7.4.0.0 (GSDK 4.2.0 <= v < 4.4.0)

## CVE ID(s)

- This vulnerability is tracked by [CVE-2023-51392](https://nvd.nist.gov/vuln/detail/CVE-2023-51392) [1].

## Description

- An error in the psa_crypto library implementation causes the library to invoke a software implementation of AES-CCM instead of the hardware accelerator.

- This results in a reduced resistance to side channel attacks on AES-CCM operations.

### Fix/Workaround

- The recommended mitigation is to update to Gecko SDK 4.4.0, or later.

- Instructions for downloading/updating the GSDK [2] and for upgrading a project to use a new GSDK version [3] can be found in the Simplicity Studio Users Guide.

- The mitigation for this vulnerability has also been backported to the branches appearing in the following table under “Mitigated Versions.”

| Branch | Mitigated Version |
| --- | --- |
| GSDK 4.3.x | GSDK 4.3.1 or later |
| GSDK 4.4.x | GSDK 4.4.0 or later |
