### Source Product Impact Details

- BT121 and BT122 modules configured to accept small Long Term Key(LTK) sizes may be impacted.

## Description

- An attacker can use a MitM attack to make a request on behalf of a legitimate peer device for a LTK key size small enough to be brute-forceable.

- Only devices which allow small LTK sizes may be impacted.

- A paper describing this vulnerability is found here: [https://www.usenix.org/system/files/sec23fall-prepub-93-](https://www.usenix.org/system/files/sec23fall-prepub-93-) shi-min.pdf.

### Fix/Workaround

- Set the minimum LTK key size to 128 bits by calling the cmd_sm_set_minimum_key_size() API. See the [BT122 API Reference Manual](https://www.silabs.com/documents/public/reference-manuals/BT122-API-Reference-Manual.pdf) or [BT121 API Reference Manual](https://www.silabs.com/documents/public/reference-manuals/bluetooth-dual-mode-bt121-api-rm.pdf) for details.

- BT122 customers should update to Bluetooth Dual Mode SDK 1.3.0, or later from the following link: [https://www.silabs.com/wireless/bluetooth/bluetooth-br-edr-modules/device.bt122?tab=softwareandtools](https://www.silabs.com/wireless/bluetooth/bluetooth-br-edr-modules/device.bt122?tab=softwareandtools). The fix is to set the minimum LTK size to 128 bits by default in the BGScript sample applications.

- BT121 customers should update to Bluetooth Dual Mode SDK 1.9.0, or later from the following link: [https://www.silabs.com/wireless/bluetooth/bluegiga-classic-legacy-modules/device.bt121-a?tab=softwareandtools](https://www.silabs.com/wireless/bluetooth/bluegiga-classic-legacy-modules/device.bt121-a?tab=softwareandtools). The fix is to set the minimum LTK size to 128 bits by default in the BGScript sample applications.”.
