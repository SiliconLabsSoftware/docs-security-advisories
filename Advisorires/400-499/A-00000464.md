# Silicon Labs Security Advisory A-00000464 : Incorrect bounds check in Wi-Fi Commissioning MicriumOS example allows for buffer overflow

Flags: Wi-Fi

CVSS Severity: High

CVSS Base Score: 9.8, Critical

CVSS Temporal Score: 8.8, High

CVSS String: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H/E:P/RL:O/RC:C

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| “Wi-Fi Commissioning MicriumOS” example | - | GSDK | 4.2.3 and earlier | [CVE-2023-2686](https://nvd.nist.gov/vuln/detail/CVE-2023-2686) |

### Source Product Impact Details

- WF200 applications based on the “Wi-Fi Commissioning MicriumOS” example in GSDK 4.2.3 or earlier may be impacted

## Description

- The GSDK provides a Wi-Fi Commissioning MicriumOS example for the WF200 that demonstrates how to set up a Wi-Fi connection. Incorrect bounds checking in the DHCP Request parser in this example allows an attacker to perform a stack-based buffer overflow to write a payload onto the heap. This could potentially escalate to remote code execution.

- This issue is tracked in [CVE-2023-2686](https://nvd.nist.gov/vuln/detail/CVE-2023-2686) [1].

### Fix/Workaround

- Affected users should update to GSDK 4.3.0 or later as follows:
    1. In Simplicity Studio’s Help menu, select the ‘Update Software’ menu item to open the Installation Manager

    2. Click the ‘Manage installed packages’ button
    3. Select the ‘SDKs’ tab and find the ‘Gecko SDK – 32-bit and Wireless MCUs’ section
    4. If there are not currently any Installations, click the ‘Install New’ button. If there is an SDK already installed, click on the ‘…’ button next to its version number
    5. Click ‘Change Version’
    6. In the ‘Versions:’ dropdown menu, select the desired version

    7. Click ‘FINISH’
- This vulnerability can be patched directly by adding the following code between lines 181 and 182 of dhcp_server.c [2]:

        if (size != 4) {
            return 0; // Reject packets that don't have an IPv4 address
        }
