# Silicon Labs Security Advisory A-00000059 : Confusion Pairing Vulnerability in Bluetooth LE and Bluetooth BR/EDR

Flags: Bluetooth

CVSS Severity: Medium

CVSS String: CVSS:3.1/AV:A/AC:L/PR:N/UI:R/S:U/C:H/I:L/A:N

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| ------- | ---------------- | -------- | ---------------- | --- |
| All Bluetooth products | See advisory | - | - | [CVE-2020-10134](https://nvd.nist.gov/vuln/detail/CVE-2020-10134) |

## Description

- A user may be vulnerable to a man-in-the-middle attack during device pairing due to pairing method confusion.

- To exploit this vulnerability, an attacker creates connections with two devices. On one device, a numeric comparison pairing procedure is negotiated. On the other device, a passkey pairing procedure is negotiated. The user must then mistakenly enter the numeric compare value as the passkey value and accept pairing on the numeric compare device. This allows the attacker to authenticate on both devices and to act as a man- in-the-middle.

- Note: This vulnerability is not bound to the hardware or Bluetooth stack and cannot be fixed by a hardware or stack change. The vulnerability can be addressed in end-product documentation and user interface design to ensure customers do not get confused about the pairing method the product is supposed to use.

- For more information, see the following links:

  - [Bluetooth SIG's vulnerability statement](https://www.bluetooth.com/learn-about-bluetooth/bluetooth-technology/bluetooth-security/method-vulnerability/)

  - [VU#534195](https://www.kb.cert.org/vuls/id/534195/)

  - [CVE-2020-10134](https://nvd.nist.gov/vuln/detail/CVE-2020-10134)

### Fix/Workaround

- If possible, the application UI should clearly differentiate between passkey and comparison pairing procedures to eliminate user confusion.

- User documentation should also emphasize the differences between passkey and comparison pairing methods to prevent this confusion.

- Additional guidance can be found in Bluetooth SIG's [statement](https://www.bluetooth.com/learn-about-bluetooth/bluetooth-technology/bluetooth-security/method-vulnerability/) on this vulnerability.
