# Silicon Labs Security Advisory A-00000200 : mbedTLS ECDSA private key vulnerabilities in Gecko SDK versions 2.7.x and earlier

Flags: Bluetooth, Zigbee, Wi-Fi, MCU

CVSS Severity: Medium

CVSS Base Score: 4.7

CVSS Temporal Score: 4.2

CVSS String: [CVSS:3.1/AV:L/AC:H/PR:L/UI:N/S:U/C:H/I:N/A:N/E:P/RL:O/RC:C](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:L/AC:H/PR:L/UI:N/S:U/C:H/I:N/A:N/E:P/RL:O/RC:C)

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| Mbed TLS | 2.18.x and earlier | GSDK | 2.7.x and earlier | [CVE-2019-16910](https://nvd.nist.gov/vuln/detail/CVE-2019-16910), [CVE-2019-18222](https://nvd.nist.gov/vuln/detail/CVE-2019-18222), [CVE-2020-10932](https://nvd.nist.gov/vuln/detail/CVE-2020-10932) |

### Source Product Impact Details

- Only EFR32, EFM32, and EZR32 SoCs and modules that run application code, built with Gecko SDK versions 2.7.x or earlier, that calls the mbedTLS implementation of the function mbedtls_ecdsa_sign(), either directly or indirectly.
- Notes:
    - The use of mbedtls_ecdsa_sign() on IoT end nodes is fairly uncommon in current deployments. Application code that does not call mbedtls_ecdsa_sign() is not susceptible to any of the vulnerabilities in this document.
    - Projects for Series 0 and Series 1 devices built upon Gecko SDK 2.7.x that call mbedtls_ecdsa_sign() are impacted.
    - Projects for Series 2 devices built upon Gecko SDK 2.7.x will use an alternate implementation of the mbedtls_ecdsa_sign() function by default. These alternate versions are not vulnerable to the issues described in this document. However, a user may edit the default configuration to undefine MBEDTLS_ECDSA_SIGN_ALT, which will cause the vulnerable implementation to be used.
    - Silicon Labs stacks (including Bluetooth, Zigbee, Connect, Wi-Fi, and others) do not call the vulnerable implementation of mbedtls_ecdsa_sign() and thus are not affected by the issues described in this document in any version of the Gecko SDK.

## Description

- mbedTLS has released several security advisories relating to ECDSA side-channel attacks that affect some versions of the mbedTLS library that are included in the Gecko SDK.
- These attacks may allow an attacker to recover part or all of the user’s ECDSA private key when the application calls the default mbedTLS implementation of the mbedtls_ecdsa_sign() function.
- Gecko SDK Versions 2.7.x and earlier contain versions of the mbedTLS library that are vulnerable to some or all of these issues.

- The vulnerable implementation of mbedtls_ecdsa_sign() can be found in ‘ecdsa.c’ under util/third_party/mbedtls/library/ in the Gecko SDK base directory. The Gecko SDK can be found in the Simplicity Studio install directory under /developer/sdks/gecko_sdk_suite/.

- Silicon Labs stacks do not call the vulnerable implementation of mbedtls_ecdsa_sign(), and thus are not vulnerable to these issues. However, a user may be exposed to these issues if they call the vulnerable function in their own application code.
- See Table 1 below for a list of these vulnerabilities and links to details about each.
- See Table 2 below for a list of SDK versions and the issues to which they are vulnerable.

| CVE # | Security Advisory Link | Fixed in mbedTLS version | Fixed in Gecko SDK versions |
| --- | --- | --- | --- |
| [CVE-2019-16910](https://nvd.nist.gov/vuln/detail/CVE-2019-16910) | Side channel attack on deterministic ECDSA | 2.7.12, 2.16.3 | 2.7.7 and later, 3.0.0 and later |
| [CVE-2019-18222](https://nvd.nist.gov/vuln/detail/CVE-2019-18222) | Side channel attack on ECDSA | 2.7.13, 2.16.4 | 3.0.0 and later |
| [CVE-2020-10932](https://nvd.nist.gov/vuln/detail/CVE-2020-10932) | Side channel attack on ECDSA | 2.7.15, 2.16.6 | 3.0.0 and later |

### Fix/Workaround

- Upgrade to Gecko SDK version 3.0.0 or later: Gecko SDK versions starting with 3.0.0 contain a version of mbedTLS that is not affected by these issues. The latest Gecko SDK can be obtained from Simplicity Studio.
- Manually patch mbedTLS: If it is not possible to upgrade to Gecko SDK 3.0.0 or later, mbedTLS can be upgraded manually in your copy of the Gecko SDK 2.7.x by following the instructions below.
    - Download the latest patch release of the 2.7 branch of the mbedTLS library (2.7.18 at the time of this writing).
    - Copy the contents of the new library into the /developer/sdks/gecko_sdk_suite/2.7/util/third_party/mbedtls directory within your Simplicity Studio install directory (typically C:\SiliconLabs\SimplicityStudio\v5). Overwrite the existing contents, but do not delete any files or folders before performing the copy.
    - Re-build your application with the new mbedTLS library.
    - The mbedtls/include/mbedtls/version.h file will contain the version number of your mbedTLS installation.

Note: Silicon Labs stacks are not tested against alternative versions of mbedTLS – users must perform their own validation to ensure correct operation if manually modifying the Gecko SDK.
