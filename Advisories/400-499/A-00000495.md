# Silicon Labs Security Advisory A-00000495 : Zigbee unauthenticated denial of service via manipulating network sequence number

Flags: Zigbee

CVSS Severity: Medium

CVSS Base Score: 7.5, High

CVSS Temporal Score: 6.7, Medium

CVSS String: [CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H/E:P/RL:O/RC:C](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H/E:P/RL:O/RC:C)

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| EmberZNet | 7.3.2 | GSDK | 4.3.2 and earlier | [CVE-2023-6874](https://nvd.nist.gov/vuln/detail/CVE-2023-6874) |

### Source Product Impact Details

- Zigbee-capable SoCs and associated modules running Ember ZNet before 7.4.0

## CVE ID(s)

- [CVE-2023-6874](https://nvd.nist.gov/vuln/detail/CVE-2023-6874)[1] has been reserved for this issue.

## Description

- An attacker may be able to cause a denial of service by intentionally advancing the network sequence number which is not encrypted.

- By spoofing messages from a certain source node to a specific destination node, the attacker can cause all messages from the source node to be ignored by the destination node until the destination node’s unicast table is purged.

### Fix/Workaround

- This issue is mitigated by no longer adding unencrypted messages to the unicast table for duplicate checking.

- Affected users should upgrade to Gecko SDK 4.4.0, or later. Instructions for downloading/updating the GSDK can be found in the Simplicity Studio Users Guide here Simplicity Studio User's Guide [2]
