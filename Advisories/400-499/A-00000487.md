# Silicon Labs Security Advisory A-00000487 : TrustZone Implementation allows untrusted code to access trusted region data

Flags: Security

CVSS Severity: High

CVSS Base Score: 9.3, Critical

CVSS Temporal Score: 8.4, High

CVSS String: [CVSS:3.1/AV:L/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H/E:P/RL:O/RC:C](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:L/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H/E:P/RL:O/RC:C)

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| - | - | GSDK | 4.3.x and earlier |[CVE-2023-4280](https://nvd.nist.gov/vuln/detail/CVE-2023-4280) |

### Source Product Impact Details

- All Series 2 devices, EFR32xG2x-based SoCs and associated modules with the following conditions:
    - With TrustZone enabled
    - Running GSDK 4.3.x and earlier

- APIs that meet the following criteria are impacted
    - Accept a pointer to a structure or other fixed-size object
    - Are part of one of the following installed services : NVM3 Service for TrustZone Secure Key Library, SE Manager Service for TrustZone Secure Key Library, or PSA Attestation Service for TrustZone Secure Key Library

## CVE ID(s)

- [CVE-2023-4280](https://nvd.nist.gov/vuln/detail/CVE-2023-4280)[1]

## Description

- An unvalidated input to an API on the secure (trusted) side of TrustZone can lead to a call from the non- secure (untrusted) side of TrustZone to read/write memory in the secure region of memory.
    - The impacted API is sl_se_get_version.

### Fix/Workaround

- Affected users should upgrade to Gecko SDK 4.4.0, or later.Instructions for downloading/updating the GSDK can be found in the Simplicity Studio Users Guide here Simplicity Studio User's Guide [2]
- This issue is documented as bud id #1184678 in the Release notes [3]
