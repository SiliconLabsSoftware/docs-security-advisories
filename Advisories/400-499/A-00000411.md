### Source Product Impact Details

- No Silicon Labs products are directly impacted

## Description

- No Silicon Labs products directly use the vulnerable uClibC open-source C library.

- The DNS libraries used by Silicon Labs products are not susceptible to DNS-Cache poisoning.

- However, application host processors which run DNS clients that are connected to Silicon Labs’ SoCs or modules that are acting as network co-processors (NCPs) or radio co-processors (RCPs) may still be vulnerable if they use the impacted library.

- This issue is being tracked as [CVE-2022-30295](https://nvd.nist.gov/vuln/detail/CVE-2022-30295), [VU#473698](https://kb.cert.org/vuls/id/473698) and ICS-VU-638779.

- More detailed information is available on the researcher’s blog post [here](https://www.nozominetworks.com/blog/nozomi-networks-discovers-unpatched-DNS-bug-in-popular-c-standard-library-putting-iot-at-risk/?utm_source=twitter&utm_medium=social&utm_term=nozominetworks&utm_content=15309652-eb80-4f93-9873-07aa97f6cef2).

### Fix/Workaround

- Affected users should contact their TCP/IP stack providers for a solution
