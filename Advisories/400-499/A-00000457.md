- Reference code from Silicon Labs’ Z/IP Gateway 7.18.02 and earlier and Unify Gateway 1.3.1 and earlier are impacted

- As of the publication of this advisory, there is no evidence these vulnerabilities have been exploited by threat actors

## Description

- All vulnerabilities except [CVE-2023-3110](https://nvd.nist.gov/vuln/detail/CVE-2023-3110) have been confirmed on the ZIP Gateway 7.18.02 reference design

- [CVE-2023-0972](https://nvd.nist.gov/vuln/detail/CVE-2023-0972) was additionally discovered in the Unify Gateway 1.3.0 reference design, and has been given its own designation: [CVE-2023-3110](https://nvd.nist.gov/vuln/detail/CVE-2023-3110)

[CVE-2023-0972](https://nvd.nist.gov/vuln/detail/CVE-2023-0972) (Z/IP), [CVE-2023-3110](https://nvd.nist.gov/vuln/detail/CVE-2023-3110) (Unify) – S0 Decryption Overflow attack

- Buffer overflows in the S0 decryption function may allow remote code execution. Due to a logical defect, S0 decryption occurs on all incoming S0 packets regardless of if S0 is enabled. Disabling S0 support DOES NOT prevent this vulnerability.

- An attacker does not need to know the network key to perform this attack

- This defect has been confirmed in BOTH Z/IP and Unify gateway products 

[CVE-2023-0971](https://nvd.nist.gov/vuln/detail/CVE-2023-0971) – Multi-Command Encapsulation privilege escalation leak

- Z/IP Clients connecting to the Gateway use a special security class to designate that their commands came from a control network

- Due to a logical defect, this elevated security classification may be misapplied to multiple commands in a multi- command encapsulated message

- Certain commands can be combined to allow an attacker without knowledge of the network key to promote messages such that they appear to originate from a local client

[CVE-2023-0970](https://nvd.nist.gov/vuln/detail/CVE-2023-0970) – Serial API Overflow attack

- Missing boundary checks in the serial API may allow an attacker to overwrite global memory, typically fewer than 75 bytes

- This attack requires a physical connection to the Z/IP Gateway’s UART

[CVE-2023-0969](https://nvd.nist.gov/vuln/detail/CVE-2023-0969) – Maintenance command read overflow

- An attacker with an authenticated device on a Z-wave network can potentially use a maintenance packet to perform a read overflow, extracting up to 660KiB from the Z/IP Gateway process over the mesh network

- Memory extracted from Z/IP Gateway may be used to reveal stack canaries or de-obfuscate return addresses

### Fix/Workaround

- To mitigate these vulnerabilities in Z/IP Gateway, update to version 7.18.3 or later as follows:
    1. In Simplicity Studio 5 click , or navigate to “Help > Update Software > Manage Installed Packages”
    2. In the Installation Manager, select the “SDKs” tab and navigate to “Z-Ware and Z/IP Gateway,” to download “Z-Wave Z-IP Gateway SDK 7.18.3.0” or later
    3. A Debian installer is found at: C:\\\<SiliconLabs>\SimplicityStudio\v5\developer\sdks\zwave\zip_gateway\\\<version>\\\<release>\Binaries
    4. Follow the [Z-Wave gateway installation guide](https://docs.silabs.com/z-wave/latest/z-wave-training-labs/gateway-session1-basic-lab) [1] to update your gateway firmware

- To mitigate these vulnerabilities in Unify Gateway, update to version 1.3.2 or later as follows:
    1. Clone Unify Gateway from the SiliconLabs/UnifySDK github repository [2] 

            git clone [https://github.com/SiliconLabs/UnifySDK.git](https://github.com/SiliconLabs/UnifySDK.git)

    2. Checkout the tag for release 1.3.2 or greater...

            git checkout ver_1.3.2

    3. Build and deploy following the [Unify Build Guide](https://siliconlabs.github.io/UnifySDK/doc/readme_building.html) [3]
    4. The binaries for this release can be found under the [“Releases”](https://github.com/SiliconLabs/UnifySDK/releases) [4] page within the SiliconLabs/UnifySDK Repository

- Please note that advanced compiler support for position independent code, enabled by default in Z/IP and Unify makefiles, can reduce the likelihood of buffer overrun vulnerabilities like these from successfully enabling an attack

    - If using the Silicon Labs default toolchain, do not disable the PIC/PIE compile options
    - If using an external toolchain, ensure position independent code is enabled
    - Ensure Address Space Layout Randomization is enabled on your gateway’s operating system
