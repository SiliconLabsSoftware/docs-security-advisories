# Silicon Labs Security Advisory A-00000456 : Lack of entropy before PSA crypto initialization causes initialization failure

Flags: Security

CVSS Severity: -

CVSS String: -

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| - | - | GSDK | 4.1.0 and earlier | - |

### Source Product Impact Details

- GSDK versions prior to 4.1.1.0 (exclusive).

Associated Bug Identifier(s): 859224, 937813

## Description

- PSA Crypto is a standard security API providing functionality such as cryptography and random number generation. When PSA Crypto is initialized, it requires an entropy source to seed random number generation.

- Some Silicon Labs services enabled in sl_service_init(), such as Co-Processor Communication (CPC), initialize PSA Crypto. GSDK protocol stacks initialize RAIL in sl_stack_init(), which is called after sl_service_init(). This results in a PSA Crypto initialization failure because the radio entropy source to seed the random number generator is not available yet.

- Note that this PSA Crypto initialization failure can happen for any application that initializes PSA Crypto before the radio.

## Impact Statement

- EFR32MG1, EFR32MG13, and EFR32MG14 devices based on the affected GSDK version (see information above) are susceptible to this issue. Such devices cannot connect to CPCD if security is enabled (which it is by default).

## Root Cause Overview

- EFR32MG1 and EFR32MG14 devices do not have a dedicated TRNG. Rev A-C EFR32MG13 devices have a faulty TRNGs (refer to MG13 errata for more details [1]). Due to this, the ADC and the radio are the only available entropy sources on these devices. The radio is the default entropy source.

### Fix/Workaround

- This has been fixed in GSDK 4.1.1.0. The GSDK has been changed to fall back to request entropy from the ADC if the radio return 0 bytes of entropy. The prerequisite is that the user must configure the ADC as an entropy source.

[1] [https://www.silabs.com/documents/public/errata/efr32mg13-errata.pdf](https://www.silabs.com/documents/public/errata/efr32mg13-errata.pdf)
