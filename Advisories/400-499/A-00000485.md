### Source Product Impact Details

- All Secure Vault High (EFx32xG2xB) SoCs and associated modules except EFR32xG21B.

## CVE ID(s)

- [CVE-2023-5138](https://nvd.nist.gov/vuln/detail/CVE-2023-5138)

## Description

- By default, the impacted products only detect glitch tamper events when the secure engine (SE) is actively executing code. Glitch tamper events will not be triggered if only the host (Cortex-M33) processor is actively executing code.

### Fix/Workaround

- Affected users should update to Gecko SDK 4.4.0 or later according to the instructions below, and make a call to the following API to put the secure engine (SE) in active mode:
    - sl_se_enter_active_mode()
    - Note: entering active mode will increase the current consumption of the chip significantly and prevent the system from entering EM2/3/4 since the SE is running. To allow entering EM2/3/4 one must call the corresponding exit active mode function, sl_se_exit_active_mode().

- Instructions for downloading/updating the GSDK can be found in the Simplicity Studio Users Guide here: Simplicity Studio User's Guide [1] 

- The following GSDK releases addresses the vulnerability. Customers are always recommended to upgrade to the latest GSDK version.
