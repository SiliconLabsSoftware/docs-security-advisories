### Source Product Impact Details

- EFx32xG1 SoCs and modules running GSDK 4.2.1 or earlier using either keys that are not 4-byte aligned or PSA oneshot CCM functions may be impacted

- EFR32xG21 SoCs and modules running GSDK 4.2.1 or earlier using keys that are not 4-byte aligned may be impacted

- EFR32xG22 SoCs and modules running GSDK 4.2.1 or earlier using the PSA CRYPTOACC transparent key agreement function may be impacted

## Description

- Some PSA Crypto functions create local copies of input key buffers to reformat the data (for example, if the input key buffer size is not a multiple of 4 bytes, it may need to be copied to a buffer that is 4-byte aligned). After the computation is done, the local copy is cleared out so that no key material is leaked out of RAM. Due to a bug in affected versions of the GSDK, the function that clears out these local copies may be optimized out by the compiler, and copies of key material could be left in RAM after the function returns.

- This key duplication is only present in RAM, so an attacker would need a way to read out memory from the device without resetting or powering off the device.
    - For devices without Secure Key Storage: An attacker that can read out RAM can likely read the key our of its non-volatile storage regardless, so accidentally duplicating it to RAM doesn’t significantly impact the confidentiality of the key.
    - For devices with Secure Key Storage: If the key is wrapped during the impacted function, then only the wrapped version of the key would be copied into RAM, which is useless to an attacker. If the attacker is present during or immediately after the initial key import, then they could potentially read the duplicated plaintext key out of RAM after the original had already been erased. Note that this would require the attacker to have RAM reading privileges on the device around the time that private keys are being provisioned.

- For EFR32xG21, this key duplication bug impacts only key buffers of a size that is not a multiple of 4 bytes, such as SECP521 and custom HMAC keys. Standard AES keys and ECC keys (excluding SECP521) are not impacted.

### Fix/Workaround

- Affected users should upgrade to GSDK 4.2.2 or later as follows:
    1. In Simplicity Studio’s Help menu, select the ‘Update Software’ menu item to open the Installation Manager
    2. Click the ‘Manage installed packages’ button
    3. Select the ‘SDKs’ tab and find the ‘Gecko SDK – 32-bit and Wireless MCUs’ section
    4. If there are not currently any Installations, click the ‘Install New’ button. If there is an SDK already installed, click on the ‘…’ button next to its version number
    5. Click ‘Change Version’

    6. In the ‘Versions:’ dropdown menu, select the desired version
    7. Click ‘FINISH’
