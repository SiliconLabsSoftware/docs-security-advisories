# Silicon Labs Security Advisory A-00000466 : Lack of PSA Crypto multithreading support could lead to resource conflicts

Flags: Security

CVSS Severity: Medium

CVSS Base Score: 6.5, Medium

CVSS Temporal Score: 5.4, Medium

CVSS String: [CVSS:3.1/AV:L/AC:H/PR:L/UI:N/S:U/C:H/I:L/A:H/E:U/RL:O/RC:R](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:L/AC:H/PR:L/UI:N/S:U/C:H/I:L/A:H/E:U/RL:O/RC:R)

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| - | - | GSDK | 4.2.3 and earlier | - |

### Source Product Impact Details

- EFR32/EFM32 SoCs and modules using PSA Crypto in multithreaded applications on GSDK 4.2.3 or earlier may be impacted

## Description

- PSA Crypto is a cryptography API which provides a standard interface for controlling cryptography primitives such as hardware accelerators and RNGs. PSA Crypto is not thread safe [1], meaning that multiple threads using PSA Crypto to access the same underlying resources may interfere with each other. Work is in progress to make PSA Crypto thread safe [2].

    - The PSA Crypto implementation available in the GSDK was updated in 4.3.0 to implement the upstream fix [2].

- Without proper multithreading support in PSA Crypto, two threads may collide when trying to access the same cryptography resource.
    - In the case of an RNG collision, this can result in both threads using the same random number.
    - In the case of a key importing/generation collision, both threads may be assigned the same key slot, resulting in the key for one thread being lost and replaced with the key from the other thread.

- Silicon Labs has seen no evidence that this issue has been causing crashes on multithreaded applications. This suggests that the frequency of unintentional collisions is low.

- Most EFR32/EFM32 applications do not isolate memory between threads, so an attacker who has enough control of one thread to intentionally trigger collisions with another thread likely has simpler methods available to access cryptographic resources of the other thread.

### Fix/Workaround

- Affected users should update to GSDK 4.3.0 or later. Instructions for downloading/updating the GSDK [3] and for upgrading a project to use a new GSDK version [4] can be found in the Simplicity Studio Users Guide.

## Certification Impact

- Certified devices that apply this update may need to be re-certified, depending on the conditions of the certification body.
