# Silicon Labs Security Advisory A-00000400 : Security Advisory for Zigbee Denial-of-Service

Flags: Zigbee

CVSS Severity: Medium

CVSS Base Score: 6.7, Medium

CVSS Temporal Score: 6.2, Medium

CVSS String: [CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H/E:H/RL:O/RC:C](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H/E:H/RL:O/RC:C)

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| EmberZNet | 7.0.2 and earlier | GSDK | 4.0.2 and earlier  | - |

### Source Product Impact Details

- Ember ZNet-capable products such as EFR32 SoCs and associated modules, running Ember ZNet 6.2.0 through 7.0.2 and including support for Green Power, with the following exception:

- Zigbee sleep end devices (SEDs) actively joined to a network are not impacted

## Description

- A malformed IEEE 802.15.4 packet causes an assert which leads to a reset and immediately clears the error.

| Bug ID # | Description | Impacted versions | Impacted Components | Recovery Mechanism | Requires NWK Key? |
| --- | --- | --- | --- | --- | --- |
| 825960 | Memory access ASSERT() on receipt of malformed Zigbee packet | Ember ZNet 6.2.0 and later | Green Power | ZNet stack will will reset the device as soon as the ASSERT occurs, packet clearing the error | No |

### Fix/Workaround

- Users of Ember ZNet 6.5.0 through 6.10.x can workaround this issue by enabling and using the packet handoff plugin as follows: 
    1. Open the project’s isc file and select the ‘plugins’ tab 
    2. Search for the ‘Packet Handoff’ plugin and enable it by clicking the checkbox. 
    3. Uncheck the ‘Handoff All Packets’ checkbox and check the ‘Handoff Raw Mac’ checkbox. 
    4. Select the ‘callbacks’ tab in the ISC file then search for ‘incoming’ and click the ‘+’ to expand the results. 
    5. Check the ‘Incoming Packet Filter’ callback.
    6. Add an implementation of the ‘emberAfIncomingPacketFilterCallback’ as shown in our [Github](https://github.com/SiliconLabs/PSIRTWA/tree/main/A-00000400), to the project’s \<project name>_callbacks.c file.

- Users of Ember ZNet 7.0.x can work around this issue by installing and using the ‘packet handoff’ software component as follows: 
    1. Open the software components dialog by double-clicking the slcp file in the project.
    2. Search for the ‘Packet Handoff’ component and click the install button.
    3. Click the configure button to open the configuration settings.
    4. Turn off the ‘Handoff All Packets’ option and turn on the ‘Handoff Raw Mac’ option.
    5. Add an implementation of the ‘emberAfIncomingPacketFilterCallback’ as shown in our [Github](https://github.com/SiliconLabs/PSIRTWA/tree/main/A-00000400) to the project’s app.c file.

- Users of Ember ZNet can also update to Ember ZNet 7.10 or later which is delivered as part of Gecko SDK 4.10 or later, which is part of Gecko SDK v 2.3.0 or later, when it becomes available as follows: In Simplicity Studio’s ‘help’ menu, select the ‘Update Software’ menu item, then click the ‘Manage Installed Packages’ button, select the SDKs tab, set the ‘category’ filter to ‘Ember ZNet (zigbee)’ and click the ‘Update’ button. Once the update is complete, the workarounds described above are no longer necessary.

- Users of older versions, 6.2.0 through 6.4.x inclusive, of Ember ZNet should upgrade to one of the versions mentioned above to take advantage of the workaround or official fix.
