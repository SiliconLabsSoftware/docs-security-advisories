# Silicon Labs Security Advisory A-00000418 : Unsecure rejoin requests on closed Zigbee networks result in coordinator crash and DoS

Flags: Zigbee

CVSS Severity: Medium

CVSS Base Score: 6.5, Medium

CVSS Temporal Score: 6.2, Medium

CVSS String: [CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H/E:H/RL:O/RC:C](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H/E:H/RL:O/RC:C)

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| EmberZNet | 7.0.2 and earlier | GSDK | 4.0.2 and earlier | - |

### Source Product Impact Details

- EFR32 and EMxxx Zigbee SoC’s and Modules running EmberZNet 7.0.2 (distributed with GSDK 4.0.2) and earlier may be impacted

## Description

- If a Zigbee coordinator receives an unsecure rejoin request after the network has been PermitJoinClosed, the coordinator should respond with the network key so the end node can reconnect. A bug in EmberZNet 7.0.2 and earlier causes this process to fail. The failure behavior depends on the version, as described below.


| Bug ID # | Description | Impacted versions | Impacted Components | Recovery Mechanism | Requires NWK Key? |
| --- | --- | --- | --- | --- | --- |
| 831183 | If a coordinator receives an unsecure rejoin request after the network has been PermitJoinClosed, the coordinator will fail to send the network key, resulting in a rejoin failure | EmberZNet 6.7.10 and earlier | Zigbee PRO stack library | For end devices to rejoin the network, the coordinator would need to re-open the network | No |
| 831183 | If a coordinator receives an unsecure rejoin request after the network has been PermitJoinClosed, the coordinator will undergo a Bus Fault | EmberZNet versions >= 7.0.0 and <= 7.0.2 | Zigbee PRO stack library | The Bus Fault will lead to a reset, returning the coordinator to normal behavior | No |

### Fix/Workaround

- Affected users should upgrade to EmberZNet 7.1.0 (distributed with GSDK 4.1.0) or later. 
    1. In Simplicity Studio’s Help menu, select the ‘Update Software’ menu item to open the Installation Manager 
    2. Click the ‘Manage installed packages’ button
    3. Select the ‘SDKs’ tab and find the ‘Gecko SDK – 32-bit and Wireless MCUs’ section
    4. If there are not currently any Installations, click the ‘Install New’ button. If there is an SDK already installed, click on the ‘...’ button next to its version number
    5. Click ‘Change Version’
    6. In the ‘Versions:’ dropdown menu, select the desired version
    7.   Click ‘FINISH’
