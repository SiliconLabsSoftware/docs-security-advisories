### Source Product Impact Details

- All Arm TrustZone Cortex-M devices using TrustZone, not specific to Silicon Labs parts.

## Description

- Researchers have demonstrated a working microarchitectural timing side-channel attack on TrustZone- enabled Cortex-M devices. This is not considered a failure of the protection offered by the architecture.
- In some circumstances a non-secure world application can infer information about the secret state of a secure world application. This may occur when there are timing variations that can happen with certain ill- advised memory access and control-flow patterns in a secure world application which could impact timing of access for a non-secure world application to a similar memory region on the bus. These timing variations could be used by a malicious non-secure world application to determine some state information from the secure world application.
- Silicon Labs would like to take this opportunity to highlight that our TrustZone-based solution for cryptographic key storage and operation builds on software that follows secure coding best practices; control-flow patterns that depend on key material (or otherwise sensitive data) is avoided to the greatest extent possible.

### Fix/Workaround

- While there is no fix required or feasible, there are steps that developers of secure world TrustZone-M applications can take to reduce the likelihood of such leakage.
- Developers must limit access to secure information until it is necessary to do so, and care must be taken to match control-flow of the execution timing of secure information to non-secure information. This may be achieved by reducing the frequency of access to secure information, and by normalizing pass/fail execution flow access times which can be achieved by accessing similar memory regions and obfuscating operations of secure functions. Additionally a cryptographically secure RNG could be employed to add jitter to execution times during secure world application access to secure memory.
