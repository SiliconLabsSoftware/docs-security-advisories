# Silicon Labs Security Advisory A-00000360 : Invalid Zigbee Packet causes Assert leading to Temporary Denial-of-Service

Flags: Zigbee

CVSS Severity: Medium

CVSS Base Score: 6.5, Medium

CVSS Temporal Score: 5.9, Medium

CVSS String: [CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H/E:P/RL:O/RC:C](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H/E:P/RL:O/RC:C)

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| EmberZNet | 6.2.3 and earlier | GSDK | 2.2.3 and earlier | - |

### Source Product Impact Details

- EFR32- and EFM3xx-based modules and SoCs running EmberZNet 6.2.3 and earlier which is part of Gecko SDK 2.2.3

## Description

- A vulnerable node receives a malicious packet over the Zigbee interface which crashes the stack, resulting in a temporary denial of service while the attacked node resets itself and recovers.

| Bug ID # | Description | Impacted versions | Impacted Components | Recovery Mechanism | Requires NWK KEy? |
| --- | --- | --- | --- | --- | --- |
| 746148| Memory access ASSERT() on receipt of malformed Zigbee packet | Ember ZNet 6.2.3 and earlier | Zigbee PRO stack library | ZNet stack will reset the device as soon as the ASSERT occurs, packet clearing the error | No |


### Fix/Workaround

- Update to Ember ZNet 6.3.0 or later, which is part of Gecko SDK v 2.3.0 or later, as follows: In Simplicity Studio’s ‘help’ menu, select the ‘Update Software’ menu item, then click the ‘Manage Installed Packages’ button, select the SDKs tab, set the ‘category’ filter to ‘Ember ZNet (zigbee)’ and click the ‘Update’ button.
