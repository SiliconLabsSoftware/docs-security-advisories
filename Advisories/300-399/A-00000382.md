# Silicon Labs Security Advisory A-00000382 : Informational: GBL Encryption Does Not Guarantee Authenticity

Flags: MCU

CVSS Severity: -

CVSS String: -

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| - | - | - | - | - |

### Source Product Impact Details

- EFR32 and EFM32 SoCs and modules running Gecko Bootloader or AppLoader may be affected

## Description

- GBL encryption is used to protect the confidentiality of the upgrade image. Without access to the encryption key, the plaintext of an encrypted object cannot be read.

- While encryption does provide some incidental authenticity, it is not sufficient to guarantee Authenticity. To guarantee authenticity, either an authenticated cipher or a signature should be used. In the case of GBL files, this is supported in the form of GBL signatures (Secure Upgrades) and application signatures (Secure Boot).

- Gecko Bootloader does not use an authenticated cipher for GBL encryption. Given a properly encrypted GBL upgrade and limited knowledge of the plaintext, an attacker can create malicious GBL files that are properly encrypted, even without knowledge of the GBL decryption key itself.

- This does not allow an attacker to decrypt GBL files on its own. Access to the GBL decryption key is needed to decrypt GBL files.

### Fix/Workaround

- To guarantee authenticity of GBL upgrades, bootloaders in affected products should use Secure Upgrades. When Secure Upgrades is enabled, GBL files will not be accepted without a valid signature, regardless of if they are properly encrypted.
o    Note that when using Secure Upgrades on a device with a Communication (or Standalone)
bootloader, the host device is responsible for validating the GBL signature before sending it to the NCP/RCP. More information can be found in A-00000384.

- Additionally, to guarantee the authenticity of any image, bootloaders in affected products should use Secure Boot. When Secure Boot is enabled, unsigned images will not be allowed to execute on the device, even if they were correctly encrypted.
