# Silicon Labs Security Advisory A-00000383 : Limited flash memory prevents EFR32xG23 storage bootloaders from upgrading the bootloader or SE over-the-air

Flags: Z-Wave

CVSS Severity: High

CVSS String: -

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| SE Firmware | 2.1.7 and earlier | - | - | - |

### Source Product Impact Details

- EFR32xG23 SoC’s and modules performing over-the-air Z-Wave upgrades and running SE Firmware 2.1.7 and earlier may be impacted

- Products with sufficient external storage are not impacted (how much external storage is needed depends on the size of the application)

## Description

- Upgrading firmware over-the-air typically requires receiving the upgrade into a storage location before staging it for upgrading. Bootloader and SE firmware upgrades are staged in the application area, thereby overwriting the application, so any bootloader or SE firmware upgrade must be followed by an application upgrade.

- EFR32xG23 SoC’s and modules do not have space in user flash to hold a bootloader, application, bootloader/SE upgrade, and application upgrade in storage. This means that for Storage bootloaders with no external storage, there is not enough space to store an additional application upgrade to apply once the bootloader/SE upgrade is complete.

- More information on Gecko Bootloader can be found in [UG489](https://www.silabs.com/documents/public/user-guides/ug489-gecko-bootloader-user-guide-gsdk-4.pdf) (for GSDK 4.0) and [UG266](https://www.silabs.com/documents/public/user-guides/ug266-gecko-bootloader-user-guide.pdf) (for earlier versions of GSDK).

### Fix/Workaround

- Affected users should upgrade to SE firmware 2.2.0 or later prior to deploying the device. Instructions for programming SE firmware can be found in [AN1222](https://www.silabs.com/documents/public/application-notes/an1222-efr32xg2x-production-programming.pdf).

    - Note that Z-Wave solutions that were certified before updating the SE firmware will require re-certification after the SE firmware has been upgraded.

Upgrading Firmware with SE 2.2.0:

- SE firmware 2.2.0 added support for upgrading the SE directly from the stored GBL upgrade file without staging it first. This allows you to perform an SE-only upgrade without destroying the application. After the SE upgrade, the bootloader and application can be upgraded in a single GBL file, or two separate files.
    - To upgrade the bootloader and application in one file, the GBL upgrade file needs to be small enough to fit in the available storage slot(s). If the upgrade file is too large, you will have to use separate upgrades for the bootloader and application.
    - To upgrade the bootloader and application separately, the bootloader upgrade needs to be staged in memory after the active application so that the active application is not destroyed by the upgrade process. This requires enough available memory after the application to store the full bootloader upgrade.
