# Silicon Labs Security Advisory A-00000393 : SE firmware upgrade operation is potentially vulnerable to a fault injection downgrade attack

Flags: MCU

CVSS Severity: Medium

CVSS Base Score: 4.2, Medium

CVSS Temporal Score: 4.0, Medium

CVSS String: [CVSS:3.1/AV:P/AC:H/PR:N/UI:N/S:U/C:N/I:H/A:N/E:X/RL:O/RC:C](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:P/AC:H/PR:N/UI:N/S:U/C:N/I:H/A:N/E:X/RL:O/RC:C)

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| SE Firmware | 1.2.10 and earlier, 2.1.6 and earlier | - | - | - |

### Source Product Impact Details

- All series 2 EFR32 and EFM32 SoC and modules with a secure engine running unpatched SE firmware, i.e., EFR32xG21 and EFR32xG22 with version numbers < 1.2.11 and EFx32xG23 with < 2.1.7.

## Description

- A precisely timed fault injection attack during an SE firmware upgrade operation can potentially allow the SE firmware to be downgraded to an earlier version.

    - Please refer to this resource for an overview of this form of attack:
[https://www.sciencedirect.com/topics/computer-science/fault-injection](https://www.sciencedirect.com/topics/computer-science/fault-injection)
    - A timed fault injection attack can be used to corrupt the evaluation value in a conditional branch of code or bypass a security decision, such as a version check, or allowing an attacker access to a capability that would otherwise be disallowed.

- The downgrade image must still be a genuine Silicon Labs signed SE firmware image.

- Downgrade attacks may be part of an overall attack strategy for the attacker to utilize previously known and patched vulnerabilities in older SE firmware. Although Silicon Labs is not aware of any exploitable vulnerabilities in early versions of SE firmware, some may exist.

### Fix/Workaround

- Upgrade secure element firmware for EFR32xG21 and EFR32xG22 to >= 1.2.11. Upgrade secure element firmware for EFx32xG23 to >= 2.1.7. Please refer to these instructions for guidance on the secure engine firmware upgrade procedure: [https://www.silabs.com/documents/public/application-notes/an1222-efr32xg2x-production-programming.pdf](https://www.silabs.com/documents/public/application-notes/an1222-efr32xg2x-production-programming.pdf) (Section 4: SE Firmware Programming and/or Section 10: Field Upgrade the SE Firmware)

- Upgrade applications to use Gecko SDK 3.2.2 or greater. Please refer to the resources at this link, for guidance: [https://community.silabs.com/s/article/gecko-sdk-suite-toolchain-support](https://community.silabs.com/s/article/gecko-sdk-suite-toolchain-support)

## Other

- The patched SE firmware, i.e. 1.2.11 and greater, introduce a "breaking change" to the SE API in the function sl_se_roll_challenge(). This function is not commonly called, and projects that do not use this function are not impacted by the breaking change. Silicon Labs protocol stacks do not use this function. Impacted projects can address the issue by upgrading affected applications to Gecko SDK 3.2.2 or greater, or by patching the affected function directly, which is in the source file: "sl_se_manager_util.c" – this file is typically found at the following path: SimplicityStudio\SDKs\gecko_sdk2\util\third_party\crypto\sl_component\se_manager\src\sl_se_man ager_util.c
