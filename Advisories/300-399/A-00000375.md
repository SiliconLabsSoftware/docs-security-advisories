### Source Product Impact Details

- Various end products using combinations of Z-Wave 100, 200, 300, 500, 700, and 800 Series chipsets configured either without security, with S0 security, or with S2 security

## Description

- The following KB article from CERT lists 6 CVEs that impact various Z-Wave protocol and hardware configurations identified as VU#142629 ([https://www.kb.cert.org/vuls/id/142629](https://www.kb.cert.org/vuls/id/142629)) and described in [this research](https://ieeexplore.ieee.org/document/9663293).

Note 1 
- Silicon Labs issued Security Advisory A-00000003 on September 6, 2019, which stated that Z-Wave products certified prior to 2017 can be vulnerable to eavesdropping, replay attacks, command injection, and denial of service. These attacks are mitigated by implementing communication encryption as specified in the Z-Wave S2 security specifications. The Z-Wave Alliance has made S2 security mandatory since April 2017 in the Z-Wave Plus Certification program. 

Note 2 
- Silicon Labs issued Security Advisory A-00000006 on October 15, 2019, which was related to the FIND_NODE_IN_RANGE, SECURITY_NONCE_GET, and SECURITY_NONCE_GET_2 messages. Firmware updates for Z-Wave 500 and 700 Series chipsets mitigate some of these attacks.

### Fix/Workaround

- See the Recommendations column in the table above. For the battery drain and jamming issues, the detection of the denial-of-service events and the associated system response must be implemented at the application layer for the given use case

- Keeping the system firmware up to date can make the system more robust against these types of attacks due to improvements in the qualification and parsing of packets and commands:
    - For Z-Wave 500 Series products, make sure the impacted devices are upgraded to 6.81.06 or
later
    - For Z-Wave 700 Series products, make sure the impacted devices are upgraded to 7.12.1 or later
