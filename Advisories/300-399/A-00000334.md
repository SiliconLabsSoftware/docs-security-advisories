### Source Product Impact Details

- All EFR32 SoCs and modules running Bluetooth that support wired Packet Traffic Arbitration (PTA) coexistence with Wi-Fi may be impacted.

- All WF(M)200 Wi-Fi transceivers and WGM160P Wi-Fi modules running wired PTA coexistence with Bluetooth may be impacted.

- All Redpine products (RS9113, RS9116) running wired PTA coexistence with an external Wi-Fi or Bluetooth device may be impacted. Spectra vulnerabilities on the internal coexistence of these devices are addressed later in this security advisory.

- All Legacy Bluegiga products (BLE1xx, BT121, WF111, WF121) and all Zentri products (AMWxx6, AMW0x7) do not support PTA coexistence and are not impacted.

| Type | Description |
| --- | --- |
| Bluetooth Information Leakage | Malicious Wi-Fi chips can use jitter in REQUEST signals to detect what type of messages Bluetooth chips are sending (idle connections, notifications, or indications) |
| Wi-Fi Denial-of-Service | Malicious Bluetooth chips can perform a DoS attack against coexistent Wi-Fi chips by frequently sending prioritized REQUESTs |
| Bluetooth Denial-of-Service | Malicious Wi-Fi chips can perform a DoS attack against coexistent Bluetooth chips by incorrectly setting the GRANT signal in response to a REQUEST signal |
| Wi-Fi Information Leakage | Malicious Bluetooth chips can use REQUEST -> GRANT delay times to potentially detect when Wi-Fi chips are under high loads |

- Redpine products have an internal coexistence manager that handles arbitration between the Wi-Fi and Bluetooth modules. This coexistence manager uses a unique protocol that is not vulnerable to any of the specific CVEs listed above or to the Spectra remote code execution vulnerability, [CVE-2020-10367](https://nvd.nist.gov/vuln/detail/CVE-2020-10367).

### Fix/Workaround

- The confidentiality lost in the information leakage vulnerabilities is minimal, and the performance loss of any potential fix is greater than the security value added by preventing these vulnerabilities.

The following bullets apply to devices that implement PTA through Silicon Labs WLAN drivers:

- Bluetooth devices can detect a DoS attack using the sl_bt_coex_get_counters() function to read Bluetooth PTA counters. Refer to [AN1128](https://www.silabs.com/documents/public/application-notes/an1128-bluetooth-coexistence-with-wifi.pdf) for details.

- Once a Bluetooth device detects a DoS attack of this type, it can turn off PTA using sl_bt_coex_set_options(SL_COEX_OPTION_ENABLE, 0).

- If a Wi-Fi device detects a DoS attack of this type, it can turn off PTA using sl_wfx_pta_state(SL_WFX_PTA_OFF). Refer to [Wi-Fi Coexistence with Other 2.4 GHz Radio Protocols](https://docs.silabs.com/wifi/wf200/content-source/application-note/wifi-coexistence) for details.

- To prevent a DoS coexistence attack against a Wi-Fi device, the Wi-Fi component can be prioritized with the sl_wfx_pta_priority(PTA_PRIORITY_WLAN_MAXIMIZED) option.
