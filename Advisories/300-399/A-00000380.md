# Silicon Labs Security Advisory A-00000380 : Gecko Standalone Bootloader Vulnerability May Allow Bypassing Application Secure Boot in Some Series 2 Devices

Flags: MCU

CVSS Severity: High

CVSS Base Score: 8.3, High

CVSS Temporal Score: 7.7, High

CVSS String: CVSSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:L/I:H/A:H/E:F/RL:O/RC:C

| Product | Impacted Version | Main SDK | Impacted Version | CVE |

### Source Product Impact Details

- EFR32xG22 SoCs and modules may be impacted.

- Series 2 EFR32 and EFM32 SoCs and modules not using an OTP Sign key may be impacted.

- EFR32 and EFM32 SoCs and modules using storage bootloaders are not impacted.

- Series 0 and Series 1 SoCs and modules are not impacted.

Preconditions:

- A successful attack requires all the following conditions to be met simultaneously:

    - The device uses a Bootloader with Communication Interface (Standalone Bootloader).

    - An attacker can request that the device performs an update to an attacker controlled GBL file.

    - Secure Boot is enabled.

    - The host device does not perform signature checks on GBL upgrades.

    - The device authenticates the application signature using a key in manufacturing token storage (the last page of flash). This applies to EFRxG22 devices that do not use bootloader certificates and all other Series 2 EFR32 and EFM32 devices that do not use bootloader certificates or the OTP Sign key.

## Description

- An attacker can craft a malicious GBL file that causes arbitrary data to be written to the last page of main flash during the upgrade process. If the device is using cryptographic keys in token storage in the last page of flash, this could result in an attacker replacing the keys used for secure boot and decrypting GBL files.

- Replacing the flash Sign key this way effectively bypasses secure boot of the application.

- [CVE-2022-24936](https://nvd.nist.gov/vuln/detail/CVE-2022-24936) has been reserved for this issue.

- More information on Gecko Bootloader can be found in [UG489](https://www.silabs.com/documents/public/user-guides/ug489-gecko-bootloader-user-guide-gsdk-4.pdf) (for GSDK 4.0) and [UG266](https://www.silabs.com/documents/public/user-guides/ug266-gecko-bootloader-user-guide.pdf) (for earlier versions of GSDK).

### Fix/Workaround

- An official fix will be available in GSDK 4.0.2, available in March 2022.

- To mitigate the issue, bootloaders in affected products can be upgraded to use bootloader certificates. This will negate the risk involved with an attacker modifying the Sign key stored in the last page of flash.

- Secure Upgrades can be enabled to allow the host device to authenticate GBL upgrades before sending them to the NCP. For more information on proper use of Secure Upgrades on Standalone Bootloaders, see A-00000384.

- Instructions on how to manually patch Gecko Bootloader to fix this issue can be requested at [https://www.silabs.com/support](https://www.silabs.com/support).
