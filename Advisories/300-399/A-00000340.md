### Source Product Impact Details

- ‘Happy MitM’, aka ‘Key-Change’, describes a vulnerability in the Bluetooth Low Energy protocol when systems are configured to not use encrypted connections, regardless of manufacturer.
- Bluetooth Low Energy products from Silicon Labs include: EFR32, BLE112, BLE113, BLE121LR, BLED112, BT121, RS9113 and RS9116.

## Description

- A video presentation of this attack can be found [here](https://www.youtube.com/watch?v=imNtvpr-RF8&t=13360s) and the paper is [here](https://arxiv.org/abs/2108.07190).

- An attacker can perform a machine-in-the-middle, aka MitM, attack on Bluetooth devices using JustWorks to replace their encryption keys.

- The report also describes systems which do not warn the user when encryption fails. This warning is required by the Bluetooth specification.

- All Silicon Labs Bluetooth stacks close connections upon failed encryption and indicate an error to the application. Attacks to replace the encryption keys will fail on devices employing MitM protection.

### Fix/Workaround

- Mitigations for these vulnerabilities depend on the application’s correct use of the BLE stack security features as detailed below. Failure to do so will result in an application that is vulnerable to the attacks mentioned above. The recommended mitigations for these vulnerabilities are as follows:
    - Enable MITM protection.
    - Actively request encrypted connections as early as possible.
    - Process all events and return values from APIs.
