### Source Product Impact Details

- This affects Series 2 EFR32, EFM32 SoCs and related modules which run custom firmware that enables the ARM’s M33 TrustZone implementation that use unpatched compilers, and uses the secure FPU registers.
- This requires TrustZone to be used. Silicon Labs does not expect to support TrustZone in its stack until around 22Q2.
- Successful exploitation of this vulnerability would risk exposure of floating point data in registers, these registers do not typically hold keys or cryptographic state information.
- This is an ARM cpu issue, the mitigation of which will be applied via a compiler-based workaround.
- Silicon Labs expects few, if any, of its customers to be impacted by this vulnerability.

## Description

- More information available at [https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2021-35465](https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2021-35465)
- Requires the M33 core to be configured with CONTROL.FPCA==0, FPCCR_S.LSPACT==0, FPCCR_S.TS=1, CONTROL_S.SFPA==1, NSACR.CP10==1, and a VLLDM instruction has loaded at least one register from memory and does not complete due to an interrupt or fault.

### Fix/Workaround

- A compiler workaround is required to prevent this issue from occurring, and update from IAR and GCC is expected by 21Q4.
