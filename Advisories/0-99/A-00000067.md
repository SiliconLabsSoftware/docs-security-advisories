# Silicon Labs Security Advisory A-00000067 : Bug in RAIL_GetRadioEntropy() results in weak entropy on EFR32xG21 and related modules

Flags: Bluetooth, Zigbee

CVSS Severity: Low

CVSS String: [CVSS:3.1/AV:A/AC:H/PR:N/UI:N/S:U/C:L/I:N/A:N/E:U/RL:O/RC:C](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:A/AC:H/PR:N/UI:N/S:U/C:L/I:N/A:N/E:U/RL:O/RC:C)

## Product Impact

- EFR32xG21 SoC’s and associated modules with projects built from GSDK/Gecko Platform Version 2.7.2 or earlier whose applications call RAIL_GetRadioEntropy() directly or use the radio entropy plugin in mbedTLS. 
- EFR32xG21 SoC’s and associated modules running Zigbee or Bluetooth LE products built from GSDK 2.7.2 or earlier. 

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| ------- | ---------------- | -------- | ---------------- | --- |
| RAIL_LIB | 2.8.2 and earlier | GSDK | 2.7.2 and earlier | - |

## Description

- If RAIL_GetRadioEntropy() function is called while the radio receiver is off or shortly after the radio receiver is enabled, it can return a constant value in the first four bytes. If these bytes are used as key material or as a seed for a pseudorandom number generator, they can result in a weakening of the key which results in a low impact to confidentiality. This analysis assumes that the minimum key size or seed size is 16 bytes, which is the common key size for AES-128 and the common seed size for mbedTLS entropy functions. Clearly if the key size is only four bytes, the impact to confidentiality will be higher.

- There may be other undesirable impacts of this bug that are not related to security. For example, random sequence counters or random backoff intervals may produce repeatable behavior after device resets.

### Fix/Workaround

- Application developers can work around this issue by discarding the first 4 bytes returned from RAIL_GetRadioEntropy() after the device reset sequence.

- This issue has been patched in GSDK/Gecko Platform version 2.7.3 and later (bug ID# 469015).

- Projects built with older versions of the GSDK can be updated to a patched version and deployed to affected products.
