# Silicon Labs Security Advisory A-00000061 : Zigbee (EmberZNet) Memory Protection issue in EM3xx Devices

Flags: Zigbee

CVSS Severity: High

CVSS String: CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H/E:U/RL:O/RC:C

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| ------- | ---------------- | -------- | ---------------- | --- |
| EmberZNet | 6.7.6 and earlier | GSDK | 2.7.6 and earlier | - |

## Description

- The memory protection unit (MPU) of the ARM Cortex M3 was not being enabled at startup for EM35x and EM35xx based Zigbee applications. The MPU is used to both disallow code execution from RAM and to create a Guard Region below the CSTACK to detect stack overflows. Allowing code execution out of RAM is undesirable because it makes various attack vectors more accessible to a malicious attacker. In addition, not having the Guard Region present means that accidental or malicious stack overflows could go undetected and corrupt other program memory resulting in undefined behavior. While neither one of these is directly exploitable, turning the MPU back on creates a safer environment to prevent problems.

### Fix/Workaround

- Fixed in EmberZNet Version 6.7.7 distributed with GSDK 2.7.7 and GSDK 3.0.0
