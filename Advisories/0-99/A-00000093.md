### Fix/Workaround

- [CVE-2020-26560](https://nvd.nist.gov/vuln/detail/CVE-2020-26560) is addressed by an [erratum](https://www.bluetooth.org/errata/errata_view.cfm?errata_id=16350) to the Bluetooth Mesh profile specification.
    - For issue [CVE-2020-26560](https://nvd.nist.gov/vuln/detail/CVE-2020-26560), upgrade to Bluetooth Mesh SDK 1.7.2 or later if using SimplicityStudio v4, otherwise upgrade to Bluetooth Mesh SDK 2.0.0. Upgrades are performed using the installation manager. In Simplicity Studio, go to the help menu and select the ‘update software’ menu item. Click the ‘manage installed packages’ button, select the SDKs tab, find the ‘Bluetooth Mesh SDK’ section and click the ‘Update’ button.

- [CVE-2020-26556](https://nvd.nist.gov/vuln/detail/CVE-2020-26556), [CVE-2020-26557](https://nvd.nist.gov/vuln/detail/CVE-2020-26557) and [CVE-2020-26559](https://nvd.nist.gov/vuln/detail/CVE-2020-26559) will be addressed by the Bluetooth Mesh profile spec 1.1.
    - Two possibilities exist for mitigating these vulnerabilities:
        - Networks using an embedded provisioner can share the public key out-of-band. Refer to the Silicon Labs Bluetooth Mesh API Reference Guide, available from Simplicity Studio’s Launcher perspective, for details.
        - Networks using GATT for provisioning can use encrypted, authenticated connections with MITM protection enabled.
    - These issues will be addressed in an SDK update later this year. A follow-up advisory will be published when the fixes are available.
