# Silicon Labs Security Advisory A-00000071 : Z-Wave unsecure application frame injection between inclusion and secure bootstrapping

Flags: Z-Wave

CVSS Severity: High

CVSS Base Score: 8.8, High

CVSS Temporal Score: 7.7, High

CVSS String: [CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H/E:U/RL:O/RC:C](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H/E:U/RL:O/RC:C)

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| --- | --- | --- | --- | --- |
| Z-Wave SDK | 7.14.0 and earlier | GSDK | 2.x.x and earlier | - |

### Source Product Impact Details

- 700 and 500 series based products

## Description

- When including a Z-Wave node securely there is a window of up to 30 seconds from network inclusion ends to secure bootstrapping must start. In this window it is possible to send unsecure application frames to the node that can potentially alter the application behavior of the node.
- The attack must happen in the window between network inclusion and secure bootstrapping. Normally this window is <1s but the security specification allows for this window to be up to 30 seconds. The attacker must be physically present and within RF range of the including controller to carry out the attack.

### Fix/Workaround

- Work-around: Make sure that all application level setup is cleared when security bootstrapping is complete.
- Fixed in Gecko SDK 3.0.0 (Z-Wave 7.14.1) for ZW700
- For 500-series, implement the work-around described above in the customer application. Security bootstrapping is complete and resetting application configuration can commence when the ASSIGN_COMPLETE (for slaves) or LEARN_MODE_DONE (for controllers) callback has been received.
