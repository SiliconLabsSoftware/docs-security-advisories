# Silicon Labs Security Advisory A-00000065 : A vulnerability in a Zigbee service command may make the device susceptible to a Denial of Service attack from a malicious node on the Zigbee network

Flags: Zigbee

CVSS Severity: High

CVSS String: CVSS:3.1/AV:A/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:H/E:F/RL:O/RC:C

## Product Impact

| Product | Impacted Version | Main SDK | Impacted Version | CVE |
| ------- | ---------------- | -------- | ---------------- | --- |
| EmberZNet | 6.7.1 through 5.1.0 | GSDK | 2.7.1 and earlier | - |

## Description

- A malicious device must successfully join the network and then send the offending command to the address of the target device. Target implementations using a watchdog timer will recover from the attack via the watchdog timer reset.

### Fix/Workaround

- Option 1:

This is fixed (Bug ID #458106) in EmberZNet versions 6.7.2 (GSDK 2.7.2, 19Q4-Patch2) and later. Vulnerable devices can upgrade to the latest EmberZNet stack to mitigate the issue.

- Option 2:

Alternatively, affected customers can patch the routine themselves, as described below. The vulnerable command is a service (debug) command that executes as part of a CLI print routine and is not required for proper device operation. The command is located in the file process-global-message.c, which is delivered as source in the EmberZnet SDK. To patch the bug, replace the first code block with the second as shown below:
