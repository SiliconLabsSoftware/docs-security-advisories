# Silicon Labs Security Advisory A-00000511 : Potential loss of confidentiality due to race condition in Bluetooth controller Connection_Handle reuse

Flags: Bluetooth

CVSS Severity: Low

CVSS Base Score: 3.1, Low

CVSS Temporal Score: 2.6, Low

CVSS String: [CVSS:3.1/AV:A/AC:H/PR:N/UI:N/S:U/C:L/I:N/A:N/E:U/RL:X/RC:U](https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:A/AC:H/PR:N/UI:N/S:U/C:L/I:N/A:N/E:U/RL:X/RC:U)

### Source Product Impact Details

- Bluetooth Low Energy (BLE) Devices in NCP/SOC modes, running Silabs Bluetooth SDK versions earlier than 9.0.0
- BLE Devices using Silabs Bluetooth SDK in RCP mode are unaffected
- BG12x devices are unaffected
- Bluetooth Mesh devices are unaffected
- SiWx91x and RS911x devices are unaffected 

Please note: As of June 2024, the Gecko SDK was renamed to the Simplicity SDK, and the versioning scheme was changed fromGecko SDK vX.Y.Z to Simplicity SDK YYYY.MM.Patch#

## CVE ID(s)

- [CVE-2023-41093](https://nvd.nist.gov/vuln/detail/CVE-2023-41093) [1] is reserved for this vulnerability

## Description

- Due to a race condition potentially allowing Connection_Handle to be re-used before being freed, an attacker may be able to gain the Connection_Handle of a disconnected peer in an encrypted channel
- An attacker may be able to exploit this vulnerability to intercept packets intended to be encrypted for the disconnected peer in plaintext

### Fix/Workaround

- Affected users should upgrade to Bluetooth SDK 9.0.0 or later, delivered as part of Simplicity SDK 2024.12.0 or later. Instructions for updating the SiSDK [2] and for upgrading a project to a new SiSDK version [3] can be found in the Simplicity Studio Users Guide.
