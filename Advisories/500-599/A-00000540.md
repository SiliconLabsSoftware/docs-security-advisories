## Description

Wi-SUN utilizes the IEEE 802.11 4-Way Handshake mechanism to establish a secure communication channel between the Border Router and a Device.

- If the Border Router receives an unexpected or unsolicited second message in the handshake sequence, the authenticator resets the Anonce and PMK to zero.

- An attacker could exploit this behavior to infer network keys, potentially allowing them to decrypt and encrypt all network traffic

### Fix/Workaround

- To mitigate this vulnerability users of SiSDK 2025.6.0 should upgrade to SiSDK 2025.6.1

- Instructions for [updating the SiSDK](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-about-the-launcher/toolbar#install) and for [upgrading a project to a new GSDK version](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-getting-started/project-upgrade-new-gsdk-version) can be found in the Simplicity Studio Users Guide

- Please refer to the Wi-SUN release notes for more information for the fix implemented
