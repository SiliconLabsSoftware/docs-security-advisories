## Description

- Several vulnerabilities in the Bluetooth pairing process have been identified in the Bluetooth protocol specification.
- These vulnerabilities are collectively known as Bluetooth LE Re-pairing (BLERP). The report is found here [https://www.ndss-symposium.org/wp-content/uploads/2026-f121-paper.pdf](https://www.ndss-symposium.org/wp-content/uploads/2026-f121-paper.pdf)

- The vulnerabilities are summarized in the following table, for detailed descriptions refer to the paper in the provided link

| Vulnerability # | Description | Impacted product(s) |
| --- | --- | --- |
| 1 | Force a re-pairing with a rogue device by spoofing an already bonded device. | EFR32[1],BT122 |
| 2 | Re-pairing can use a lower security level than previous (pairing response). | EFR32[1],BT122 |
| 3 | Re-pairing with a legitimate device can use a lower security level than previous making brute-forcing the LTK easier. | EFR32[1],BT122 | 
| 4 | SMP security request (from peripheral) does not include the maximum encryption key size supported. Using a key with less than the maximum keysize makes brute-forcing the key easier. | EFR32,BT122 |

[1] EFR32 Bluetooth stack requires explicit confirmation from the user/application to perform re-pairing.

### Fix/Workaround

- Impacted users of EFR32-based products should upgrade to Bluetooth SDK 9.0.0 or later, delivered as part of Simplicity SDK 2024.12.0 or later.

- Instructions for [updating the Simplicity SDK](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-about-the-launcher/toolbar#install) and for [upgrading a project to a new Simplicity SDK version](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-getting-started/project-upgrade-new-gsdk-version) can be found in the Simplicity Studio Users Guide.

- No fix is available for BT122.
