## Description
 * Two out-of-bounds write vulnerabilities have been identified in impacted versions of EmberZNet SDK.
    * Out-of-bounds writes may lead to remote code execution if execution from RAM has not been disabled.
 * The attacker must be on the network to perform either attack.
 * For [CVE-2026-94502](https://nvd.nist.gov/vuln/detail/cve-2026-94502), the Price cluster must be supported in the network for the attack to be possible. The impacted Publish Price Matrix command is supported as a command from a server to a client, so the attacker must already be a server on the network.
 * For [CVE-2026-85079](https://nvd.nist.gov/vuln/detail/CVE-2026-85079), there is no cluster requirement. The vulnerability is in the Simple_Desc_req response, so an attacker is not able to exploit this vulnerability until the target sends a Simple_Desc_req.


### Fix/Workaround
 * To detect and prevent execution from RAM, It is recommended to include the "Platform > Security > Memory Protection Unit > Simple MPU" component in your Simplicity Studio slcp file. This component instantiates a simple driver that configures the Memory Protection Unit (MPU) to detect code injection attacks by making the RAM non-executable.
    * Note that for impacted versions of the SDK, this component is NOT included by default.
 * No fix for GSDK is available at this time.
 * Instructions for [downloading/updating the SDK](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-about-the-launcher/toolbar#install) and for [upgrading a project](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-getting-started/project-upgrade-new-gsdk-version) can be found in the Simplicity Studio Users Guide.
