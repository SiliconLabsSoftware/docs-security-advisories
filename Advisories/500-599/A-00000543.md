## Description

- 2 vulnerabilities in the third-party library Mbed TLS are being disclosed in this advisory.
    - [CVE-2025-27809](https://nvd.nist.gov/vuln/detail/CVE-2025-27809) refers to a vulnerability where a TLS client does not check the hostname of a server in a TLS handshake, allowing any server with a valid certificate to establish a TLS session.
    - [CVE-2025-27810](https://nvd.nist.gov/vuln/detail/CVE-2025-27810) refers to a vulnerability where the “TLS Finished” message was composed using uninitialized stack memory in some cases of failed memory allocation or hardware errors. This may lead to authentication bypasses, such as replay attacks.

### Fix/Workaround

- Impacted users should upgrade to Simplicity SDK 2025.12.0, or later
- Instructions for [downloading/updating the SDK](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-about-the-launcher/toolbar#install) and for [upgrading a project](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-getting-started/project-upgrade-new-gsdk-version) can be found in the Simplicity Studio Users Guide
- Additionally, client applications implementing TLS should explicitly call the mbedtls_ssl_set_hostname API to mitigate [CVE-2025-27809](https://nvd.nist.gov/vuln/detail/CVE-2025-27809).
- Mbed TLS recommends the following workaround for [CVE-2025-27810](https://nvd.nist.gov/vuln/detail/CVE-2025-27810) in [https://mbed-tls.readthedocs.io/en/latest/security-advisories/mbedtls-security-advisory-2025-03-2/](https://mbed-tls.readthedocs.io/en/latest/security-advisories/mbedtls-security-advisory-2025-03-2/)
    - “Ensure that enough memory is available before performing a handshake and that any cryptographic hardware drivers used for hash functions cannot return errors.”
