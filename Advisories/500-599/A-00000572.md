# Silicon Labs Security Advisory A-00000572 : Incorrect use of the PUF key for user key generation in EFR32xG27 results in predictable keys

## CVE ID(s)

- [CVE-2026-2815](https://nvd.nist.gov/vuln/detail/CVE-2026-2815) is reserved for this issue

## Description

- In impacted versions of the SDK, a bug in the PSA Crypto driver uses an unsupported algorithm for key derivation using the built-in PUF-based key. This results in a key that is not generated using the PUF.
- If a user application attempts to derive a key from the built-in PUF key, the derived keys will be deterministic and vulnerable to brute forcing. Because the PUF is not incorporated in the key generation, all devices attempting to derive a key from the PUF this way will derive the same key value.
- None of the protocol stacks or platform components derive keys this way, so a product is not impacted unless the application code generates a key and specifies that the PUF should be used.
- The TrustZone Root Key (TRK) correctly incorporates the device-unique PUF material and is NOT impacted by this vulnerability.

### Fix/Workaround

- In SiSDK 2025.12.2, the relevant drivers were updated so that an error is returned when trying to use the unsupported algorithm. This lowers the risk of unintentionally using deterministic keys.
- In SiSDK 2026.6.0, a compatible algorithm was implemented that allows the PUF key to be used for arbitrary key derivation. Impacted products using SiSDK should upgrade to version 2026.6.0 or later.
- GSDK is no longer maintained for Series 2 devices, including EFR32xG27, so impacted devices should upgrade to fixed versions of SiSDK.
- Instructions for [downloading/updating the SDK](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-about-the-launcher/toolbar#install) and for [upgrading a project](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-getting-started/project-upgrade-new-gsdk-version) can be found in the Simplicity Studio Users Guide.
