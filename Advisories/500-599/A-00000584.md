## Description

- Several vulnerabilities in the Bluetooth pairing process have been identified in the Bluetooth protocol specification.
- These vulnerabilities are collectively known as Bluetooth LE Re-pairing (BLERP). The report is found here https://www.ndss-symposium.org/ndss-paper/blerp-ble-re-pairing-attacks-and-defenses/
- The vulnerabilities are summarized in the following table, for detailed descriptions refer to the paper in the provided link

| Vulnerability # | Description | Impacted product(s) |
| --- | --- | --- |
| 1 | Force a re-pairing with a rogue device by spoofing an already bonded device. | SiWx917, RS9116W |
| 2 | Re-pairing can use a lower security level than previous (pairing response). | SiWx917, RS9116W |
| 3 | Re-pairing with a legitimate device can use a lower security level than previous making brute-forcing the LTK easier. | SiWx917, RS9116W | 
| 4 | SMP security request (from peripheral) does not include the maximum encryption key size supported. Using a key with less than the maximum keysize makes brute-forcing the key easier. | SiWx917, RS9116W |


### Fix/Workaround

- Impacted users of SiWx917 should upgrade to WiSeConnect v4.1.0, or later according to the instructions below

- Instructions for [updating the Simplicity SDK](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-about-the-launcher/toolbar#install) and for [upgrading a project to a new Simplicity SDK version](https://docs.silabs.com/simplicity-studio-5-users-guide/latest/ss-5-users-guide-getting-started/project-upgrade-new-gsdk-version) can be found in the Simplicity Studio Users Guide.

- Impacted users of RS9116 should upgrade to WSDK v2.14.0, or later
